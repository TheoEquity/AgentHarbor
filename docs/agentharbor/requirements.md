# AgentHarbor 完整需求文档

版本：1.4
整理日期：2026-11-07
状态：当前需求基线；包含已确认的下一阶段记忆架构，目标能力不代表已经实现

AgentHarbor 面向个人使用，把几台机器上 Codex、DeepSeek Harness、Hermes 等 Agent 的工作按项目汇总到云端。用户继续在本地开展工作，通过网页查看哪个项目由哪台机器、哪个 Agent 推进，了解任务进展与完成情况，并在同一项目内共享记忆。

本文整理已经确认的产品范围、使用方式和检查标准。实现建议与待定事项单独列出；文中的目标能力不代表已经开发完成。

下一阶段采用四类记忆，并分别管理内容状态、适用范围和来源版本。详细操作见[下一阶段需求整理](next-stage-requirements.md)，实现方案见[下一阶段技术方案](technical-design-v2.md)。本次只更新文档；原[首版技术方案](technical-design-v1.md)与[最小验收标准](acceptance.md)保留为首版阶段记录，记忆部分的后续设计以本文和 v2 为准。

## 1 产品目标与范围

首版需要完成一条完整的使用流程：添加项目，连接并关联多台机器，在本地使用 Agent，按固定周期同步工作记录，在云端查看任务，并由另一台机器取回同项目记忆继续工作。

核心功能仍为五项：项目管理、机器与 Agent、任务记录、项目记忆、定时同步。独立「任务」菜单是任务记录的跨项目入口。

| 范围 | 首版约定 |
| --- | --- |
| 使用对象 | 先供用户自己使用，管理几台机器和多个项目 |
| 云端职责 | 保存与汇总项目、机器关联、任务和记忆，提供查看及同项目记忆读取能力 |
| 本机职责 | 用户从原有 Agent 入口开始工作；共用连接程序负责项目关联、暂存和同步，Agent 适配器负责读取各自来源，并在支持时提供记忆 |
| 多 Agent | 第一版 A、B 两机均使用 Codex，同一种适配器分别识别机器与会话。接入设计仍保留按 Agent 扩展的边界；DeepSeek Harness、"龙虾"（暂按 OpenClaw 理解）、Hermes、Pi 是后续候选，候选不等于已支持 |
| 同步方式 | 固定周期上传新增或变化内容，本地检测频率与云端上传频率分开 |
| 项目代码 | 可以登记仓库链接，具体托管位置另定；首版不要求同步整个工作目录 |

首版不包含云端派发、启动、停止或重跑 Agent，也不包含任务验收、成果与版本管理、附件交付区。用量和额度放到后续，不占首版菜单入口。

## 2 基本对象与归属

| 对象 | 需要表达的含义 |
| --- | --- |
| 项目 | 云端统一的项目归属；不同机器的目录可以关联同一个项目 |
| 机器 | 一个稳定的来源标识及可读名称；修改名称不应变成另一台机器 |
| Agent 来源 | 哪台机器上的哪种 Agent；同名 Agent 在不同机器上分别识别 |
| 本地目录关联 | 机器、目录、项目与 Agent 之间的明确对应关系 |
| 任务记录 | 用户工作及其进展在云端的记录，保留来源会话和执行轮次的关联 |
| 执行轮次 | 一次开始、运行、结束或中断的执行过程；同一会话可能有多轮 |
| 项目记忆 | 可供同项目不同机器和 Agent 复用的内容，保留来源与更新时间 |
| 全局通用记忆 | 本人多个项目可选用的知识；按项目启用，不向其他项目开放项目专属内容 |
| 同步记录 | 本机事件何时发生、何时被云端接收，以及已确认的接收结果 |

不能仅凭目录名或项目显示名合并不同来源。无法确定归属时提示关联，不能猜测。采集记录需要区分会话与执行轮次，但不预先规定最终数据库结构或云端任务主键。

## 3 用户如何使用

### 3.1 第一次使用

1. 在「项目」添加名称、说明，可选填仓库链接。
2. 在「机器」查看连接说明，然后到机器 A 完成本地接入。
3. 在机器 A 选择已有项目、本地工作目录和使用的 Agent。
4. 首次上报后，在项目「参与者」中看到机器 A、Agent、目录和同步时间。
5. 在机器 B 重复接入，选择同一个已有项目并绑定 B 机自己的目录。
6. 在任一机器原来的 Agent 入口开展工作；下一轮同步后，在「任务」或项目内「任务记录」查看。页面按实际上报的机器和 Agent 来源显示，不预设 B 机使用哪一种工具。

机器接入和目录关联只需首次配置。创建云端项目本身不算本机已连接或已同步。正式安装、连接与记忆读取步骤需在适配确定后提供，不提前展示不可用的命令。

### 3.2 日常使用

| 想做的事 | 操作路径 |
| --- | --- |
| 看所有项目谁在工作 | 打开「任务」，按项目、机器、Agent 或状态筛选 |
| 查看一个任务的进展 | 点击任务行，打开详情抽屉 |
| 看某个项目的工作 | 「项目 → 目标项目 → 任务记录」 |
| 看项目有哪些参与者 | 「项目 → 目标项目 → 参与者」 |
| 查找或补充项目背景 | 「项目 → 目标项目 → 项目记忆」 |
| 整理候选记忆 | 「项目 → 目标项目 → 项目记忆 → 待整理」，核对来源后生效、纠正或停用 |
| 管理通用偏好和方法 | 「设置 → 全局记忆」；在各项目的记忆设置中选择是否使用 |
| 开启或关闭项目记忆 | 本机绑定项目时选择功能；「项目记忆 → 设置」查看项目规则与本机实际状态，具体开关分工见 v2 建议 |
| 看 Agent 取回了什么 | 「任务详情 → 记忆读取记录」 |
| 排查为什么没有更新 | 打开「同步」查看最后收到的时间及已知异常，必要时回到本机确认 |

继续、暂停或修改 Agent 工作，仍在原来的本地入口操作。网页刷新只读取云端已收到的数据，不强制远端机器立即上传。

## 4 页面结构

一级导航依次为「项目」「任务」「机器」「同步」，默认进入「项目」。「使用说明」为辅助入口。

| 页面或区域 | 展示内容 | 用户操作 |
| --- | --- | --- |
| 项目总览 | 项目名、说明、参与机器与 Agent、最近任务和更新时间 | 添加项目、进入项目、编辑项目信息 |
| 任务 | 跨项目任务列表，逐条显示项目、机器、Agent、最近状态和接收时间 | 组合筛选、搜索、打开任务详情 |
| 项目详情 | 项目信息，下设任务记录、参与者、项目记忆三个标签 | 在同一项目内切换查看 |
| 项目内任务记录 | 当前项目的任务、来源、最近状态和时间 | 按机器、Agent、状态筛选，打开详情 |
| 任务详情抽屉 | 项目与来源、时间、状态、进展时间线、简短完成说明、记忆读取记录 | 查看事件和相关记忆，关闭后返回原列表 |
| 参与者 | 本项目关联的机器、Agent、本地目录和最后同步时间 | 查看关联与连接说明 |
| 项目记忆 | 情景、语义、程序记忆，待整理或有效状态，来源及版本；工作记忆关联任务详情 | 按类型和状态筛选、收集、确认生效、更正、停用、查看设置 |
| 全局记忆 | 本人的通用知识、来源及版本，哪些项目启用了它 | 从设置进入管理；项目侧独立选择是否使用 |
| 机器 | 每台机器上的 Agent、关联项目与目录、最后上报时间 | 查看接入说明和关联详情 |
| 同步 | 各机器最近接收时间、批次、补传及可确认的异常 | 按机器查看记录 |

项目专属记忆在项目内部维护；全局记忆提供独立管理入口，不混入其他项目的私有内容。「设置 → 全局记忆」是本轮建议的入口位置，不新增工作台派发能力。产品页面不出现「接入 Multica」或内部组件配置卡片。

## 5 项目与机器管理

### 5.1 项目管理

- 支持添加和编辑项目名称、说明、仓库链接。
- 每个项目汇总自己的任务记录、参与者和记忆。
- 同一项目允许关联不同机器上的不同目录；多台机器关联后不重复创建项目。
- 新项目尚未收到记录时显示明确空状态。
- 本地项目目录与云端项目的关联需要明确确认；目录同名不构成自动归属依据。

### 5.2 机器与 Agent

- 机器使用稳定标识，显示名称可与标识分开维护。
- 同一台机器可关联多个项目和多个 Agent。
- 同一种 Agent 在不同机器上可区分；同一台机器上的不同 Agent 类型也分别展示。
- Agent 来源按实际接入和上报显示；列入候选的 Agent 不显示成已连接或已支持。
- 展示机器及关联信息截至哪次上报，不把「已关联」显示成「任务已采集」。
- 首次尚未上报、最近收到上报、状态可能过期需要能够区分。
- 云端不知道的本机实时状态保持未知。

## 6 本地采集与任务记录

### 6.1 采集要求

目标是用户直接从本地 Agent 入口开始工作后，连接程序可以记录相关变化。采集本身不得额外启动一次 Agent 执行。

- 记录能够可靠取得的标题、项目归属、来源机器、Agent、来源会话及执行轮次。
- 采集开始、进展、明确完成汇报、失败、中断和结束事件，并保留来源时间。
- 能取得简短完成说明时，随任务保存；不能取得的字段如实留空或标为未知。
- 保留已采集的各轮事件，不能因下一轮开始而覆盖上一轮记录。
- 只知道执行结束时，不能推断整项工作已完成。
- 保留来源事实，不把本地数据解析结果升级成任务验收结论。

共用连接程序负责稳定机器标识、目录与项目关联、本地事件暂存、同步游标、定时批量上传、失败重试和接收确认。每种 Agent 的适配器只负责从其实际入口读取事件，映射到统一的来源会话、执行轮次、发生时间、状态及证据；可按该入口可用的事件接口、扩展机制或只读本地记录实现。新增 Agent 原则上只增加适配器，沿用同一套上传接口、云端任务记录和页面；若统一事件不足以准确表达新来源，再单独评估契约改动，不猜测或丢弃来源事实。

Codex 的读取方式可以参考 `codex-task-monitor`；B 机若也使用 Codex，可复用同一种适配器，但保留不同机器和会话标识。DeepSeek Harness、OpenClaw、Hermes、Pi 各自的接入点和可用字段需按实际版本与入口验证。列为候选不代表适配器已经完成。

### 6.2 任务列表与详情

独立「任务」页默认展示所有项目、所有状态，按最近接收时间倒序排列。每条记录显示任务名称、所属项目、机器、Agent、最近上报状态、接收时间。

支持项目、机器、Agent、状态组合筛选，以及任务名称或编号搜索。没有符合条件的结果时显示空状态，不清空用户的筛选条件。

全局任务页与项目内任务记录使用同一批数据，打开同一任务时显示同一详情。详情应包含开始时间或可取得的本地事件时间、云端接收时间、进展时间线和简短完成说明；不具备开始时间证据时不编造。

关闭详情抽屉后返回原列表，并保留原有筛选条件和搜索词。

### 6.3 状态与异常规则

| 证据或情况 | 页面表达 |
| --- | --- |
| 尚未收到任务或机器记录 | 尚未收到同步或任务记录 |
| 收到明确运行事件 | 运行中，并显示信息截至时间 |
| Agent 明确汇报工作完成 | 已完成 · Agent 上报，并保留说明 |
| 只取得一轮执行结束事件 | 本轮已结束或完成情况未知，不自动认定整项工作完成 |
| 收到明确中断或失败记录 | 按实际记录显示中断或失败 |
| 长时间没有新上报 | 状态可能过期，保留最后已知状态 |
| 本地读取或解析失败 | 展示已上报的错误；不能据此把任务标成失败 |
| 断网后收到补传 | 保留事件原始发生时间，同时展示实际接收时间 |
| 云端收到但拒绝批次 | 展示可确认的接收失败及原因 |

不同机器分别展示数据时点，不使用单一项目更新时间掩盖其他机器的旧记录。没有上报不等于离线、失败或完成。参考工具中的「等待处理」「已处理」不作为首版新增的确认或验收流程。

## 7 记忆管理

### 7.1 四类记忆的职责

已确认采用以下四类逻辑记忆。它们不是依次升级的四个层级，也不要求四套数据库。腾讯 L0–L3 是另一种处理分层，不再作为本产品的主要分类。

| 类型 | 保存什么 | 何时使用 | 云端职责 |
| --- | --- | --- | --- |
| 工作记忆 Working Memory | 当前任务、计划、临时工具结果和执行状态 | 当前会话工作期间 | 主要由智能体会话维护；云端展示必要的任务状态和交接摘要，不复制完整内部上下文 |
| 情景记忆 Episodic Memory | 某次 Bug 修复、失败过程、任务经历 | 回顾类似问题或接续工作时检索 | 按条保留经过、结果与来源，默认不整批放入新会话 |
| 语义记忆 Semantic Memory | 已确认的目录结构、接口约束、项目事实和通用偏好 | 新会话读取必要的有效知识，详细内容按需取回 | 维护独立事实条目及其版本、状态和适用范围 |
| 程序记忆 Procedural Memory | 经过验证的操作步骤、工作流和 Skill | 遇到匹配任务时加载 | 维护适用条件、步骤和验证依据；加载不等于自动执行 |

工作记忆主要在任务详情呈现；长期内容在记忆页按类型筛选。原始材料作为来源保存，不强制每份材料都归为有效记忆。一条经历可支持新的事实或方法，提炼时保留来源关系，不把原经历移动后丢失。

### 7.2 类型、状态、范围分别管理

| 维度 | 要求 |
| --- | --- |
| 类型 | 情景、语义、程序决定如何组织和取回；工作状态保留在会话与任务记录中 |
| 状态 | 待整理或候选、有效、停用或被替代；只有有效内容进入默认知识读取 |
| 范围 | 项目专属，或本人全局通用；全局内容只向已启用的项目提供 |
| 来源与版本 | 每条有独立标识、来源、更新时间和修订版本；无法确认的来源标为未知 |

用户可按条查看、搜索、更正、生效或停用。全局记忆也遵循状态规则；其他项目不能读写当前项目的专属记忆。使用全局记忆的权限不等于修改全局记忆的权限，项目内容不能自动提升为全局内容。

### 7.3 收集、沉淀与直接记住

| 入口 | 处理规则 |
| --- | --- |
| 普通任务经历或外部材料 | 先收集并保留来源，默认待整理；上传或任务结束不代表生效 |
| 用户明确要求记住并确认的事实或规则 | 支持直接保存为有效语义或程序记忆，记录确认来源；声明为"已验证的方法"还需验证依据 |
| 智能体自己发现的事实或提炼建议 | 保存为候选，不能把推测当作用户决定或已确认事实 |
| 用户集中整理 | 查看材料与已有知识，筛选、纠正、合并后生效；保留被替代内容和来源 |

自动收集正文范围与自动整理触发时机仍待确定。当前任务事件只有状态和有限证据，不等于已采集完整 Bug 修复过程。第一步优先支持明确提交材料、人工确认和有效知识取回，再评估自动提炼。

记忆以独立条目管理，不再以每项目一份可无限追加的 L3 文档作为唯一真相。用于启动会话的简短摘要由有效条目生成，不能成为另一份独立编辑、互相覆盖的知识来源。

### 7.4 取回时机与直接云端读取

| 触发时机 | 取回内容 |
| --- | --- |
| 已启用项目的新会话 | 少量必要的有效语义知识；项目允许时加入适用的全局知识 |
| "捞一下蓝色彗星的记忆"等明确查询 | 直接向云端查询相关条目，显示来源、状态与版本，不要求指定缓存文件 |
| 回顾类似故障或接续工作 | 相关情景记忆和最近交接摘要，明确数据截至时间 |
| 遇到匹配操作 | 相关程序记忆或 Skill，先匹配适用条件，再加载详细步骤 |

服务端先检查身份、项目范围、开关和有效状态，再检索与选择内容。明确回顾原始材料时，可通过单独的历史查询返回有权限的待整理内容，并标为材料；不能把它混入有效知识默认结果。停用和被替代内容仅供管理追溯，不再当作当前知识提供。

任务和材料仍定时批量上传；新会话与显式记忆查询直接访问云端，不等待下一轮同步，不在每条提示或每次工具调用时重读全部记忆。断网时本轮云端读取失败，不悄悄用旧本地文件冒充最新结果；本机任务采集可继续。

MCP 提供主动读写入口，本身不保证启动时自动读取。新会话自动提供需要适配器的受支持入口，并验证内容进入上下文；不得为此修改 `AGENTS.md`。开启、关闭及重新开启的作用范围见下一阶段需求，已经进入当前会话的内容无法由开关撤回。

### 7.5 读取证据与冲突

入口为「任务详情 → 记忆读取记录」。展示任务、机器、智能体、触发原因、读取时间与接收时间，以及条目 ID、版本、类型、项目或全局来源、检索结果和实际提供的内容。

"已检索到""已提供给会话""智能体已使用"分别记录；没有对应证据就显示未确认。检索命中或任务继续运行不能代替上下文提供确认，后续编辑也不能改写过去读取的版本。

多机器新增不能互相覆盖，重复上传不能重复入库；编辑旧版本应报告冲突。云端内容与本地代码、当前要求或其他知识矛盾时保留证据，支持纠正、停用，不默认认定云端始终正确。已报告的未决冲突需可见，不能把争议双方都作为已确认事实使用；启动排除争议条目，显式查询标明待核实。全局与项目规则的具体冲突处理建议见 v2。

## 8 定时同步与云端保存

### 8.1 同步规则

- 本机先保存事件，再按固定周期上传新增或变化内容。
- 本地检测频率和上传频率可以不同；云端上传不跟随每一条工具结果实时发生。
- 没有新增内容时，不重复上传历史任务或会话正文。
- 断网后在本机保留未送达内容，恢复连接后补传。
- 重复发送不产生重复任务或事件，旧记录不能覆盖更新的状态。
- 任务、记忆及记忆读取事件都保留本机发生时间与云端接收时间。
- 不要求上传整个工作目录；项目代码传输不纳入本版同步范围。
- 浏览器关闭不影响本机记录和同步；本地与云端重启后需要保留各自已保存的必要记录。

云端只能展示已经掌握的同步情况。本机断网时的待传条数、网络错误和最新进展可能尚未传来，网页不能编造这些信息。

上述周期用于任务、材料和读取事件。用户通过 MCP 明确保存记忆时直接请求云端并取得确认；新会话或显式查询也直接读取，不等待定时批次。

### 8.2 使用示例

以下使用 5 分钟间隔说明过程，不代表实际间隔已经确定。

| 时间 | 本地或云端发生什么 | 用户在网页看到什么 |
| --- | --- | --- |
| 10:01 | A 机 Codex 开始任务 | 尚未同步，列表保持上一轮内容 |
| 10:05 | A 机上传任务开始与进展 | 出现任务、项目、A 机、Codex 和最近状态 |
| 10:07 | A 机 Agent 汇报完成 | 网页仍显示截至 10:05 的状态 |
| 10:10 | A 机上传完成记录与收集的任务材料 | 任务状态及说明更新，材料进入待整理；不会自动成为有效知识 |
| 后续 | B 机选用的 Agent 在支持的入口取回背景并接续工作 | 读取事件上报后，详情可查看取回内容及上下文提供情况 |

### 8.3 运行要求

云端服务持久保存项目、机器关联、任务和项目记忆，服务重启后已确认接收的记录仍在。本地连接程序独立于网页运行，不要求用户持续打开浏览器。部署地址、运行方式和具体同步周期见待定事项。

## 9 产品功能验收标准

下表是产品目标检查标准，不等于首版最小验收已全部通过。本轮更新了记忆目标；历史 M01–M05 保留在[首版验收文档](acceptance.md)，新增记忆行为见 [v2 验收场景](technical-design-v2.md#9-验收场景)。

| 编号 | 检查场景 | 通过条件 |
| --- | --- | --- |
| A01 | 多机器参与同一项目 | 第一版至少两台机器上的 Codex 来源归入同一项目，目录可以不同；后续新增 Agent 类型时再分别验证 |
| A02 | 本地直接开始工作 | 无需云端派发，任务在下一轮同步后可见；采集不额外启动 Agent |
| A03 | 同一会话连续执行多轮 | 保留各轮事件及来源关联，不被最新一轮覆盖，也不重复计入重传事件 |
| A04 | 打开全局任务页 | 默认全部项目与状态，按接收时间倒序，逐条看清项目、机器、Agent |
| A05 | 筛选与搜索 | 多条件可组合，搜索可用，无匹配时有明确空状态 |
| A06 | 两种入口查看任务 | 全局与项目内显示一致；关闭详情后保留原列表筛选与搜索 |
| A07 | 任务状态变化 | 仅按收到的证据更新；运行结束、明确完成汇报、中断和未知可以区分 |
| A08 | 某台机器长时间未上报 | 保留最后已知状态和时间，只标可能过期，不自动判断离线或失败 |
| A09 | 断网、补传、重传与乱序到达 | 记录不丢不重，最新状态不倒退，发生与接收时间分别保留 |
| A10 | 网页关闭与服务重启 | 关闭网页不影响本机记录和同步；重启后必要记录仍在 |
| A11 | 手动管理项目记忆 | 能保存、搜索、查看和编辑允许修改的内容；原文只读，来源与时间可见 |
| A12 | 四类职责与来源追溯 | 工作状态关联任务；情景、语义、程序可区分；类型、状态、范围互相独立，来源可追溯 |
| A13 | 同项目跨机器读取 | B 机可取回 A 机已同步的同项目记忆；不混入未同步内容或其他项目记忆 |
| A14 | 开始、接续和任务中查询 | 已适配入口能在相应时机读取相关背景，并记录触发原因及任务归属 |
| A15 | 检索与上下文提供不同 | 命中多条但只提供部分时，两组结果分别展示；无提供确认时不能显示已放入 |
| A16 | 读取记录尚未同步 | 云端保持尚未收到或最后已知记录，下一轮接收后显示发生与接收时间 |
| A17 | 读取失败及后续编辑 | 云端读取失败明确可见，不冒用旧缓存；旧读取内容不会被后来编辑改写 |
| A18 | Skill 内容取回 | 检索或加载内容不自动显示为流程已执行，也不改变任务完成结论 |
| A19 | 收集与生效分开 | 普通 Bug 经历或错误摘录进入待整理；未确认前不作为启动知识提供 |
| A20 | 全局记忆按项目启用 | 启用项目可读适用的全局有效条目，关闭项目不可读；项目专属内容不跨项目泄露 |
| A21 | 停用与并发编辑 | 停用不删除历史；后续读取排除停用内容，旧版本编辑不能覆盖新版本 |

## 10 技术方向与待定事项

### 10.1 已明确的方向

- 基于 Multica 作为开发底座，按本产品范围调整页面与能力。
- 第一版已接入腾讯 MemoryCore L3。下一阶段采用四类记忆、独立条目、状态与范围控制；腾讯组件的复用边界见 v2，不以默认 L0–L3 流程替代产品规则。
- 本地启动工作，云端观察与留档，固定周期增量同步。
- 优先复用已有项目和组件，但只保留完成当前需求所必需的部分。
- 本地连接程序和云端接口共用；按 Agent 的来源差异增加小适配器，不为每种 Agent 复制整套同步、记忆服务或任务页面。
- Codex 采集可参考 `codex-task-monitor` 的本机观察方式；该参考尚未接入本项目，不等于直接安装或整套复制。

### 10.2 需要在实现前或适配验证中确定

| 事项 | 当前状态 |
| --- | --- |
| Agent 实际入口 | 第一版 A、B 两机实际使用的 Codex 入口、版本和平台需记录；DeepSeek Harness、"龙虾"（暂按 OpenClaw 理解）、Hermes、Pi 等候选的事件与上下文入口须逐一验证后才能声明支持 |
| 采集能力 | 各入口可读字段、进展和完成说明、原文采集范围需验证 |
| 任务身份映射 | 保留来源会话与执行轮次；云端稳定标识和多机器映射方式需落实 |
| 同步设置 | 固定周期已确定，具体分钟数和状态过期阈值待定 |
| 记忆服务适配 | 四类职责与独立条目已确定；v2 建议 AgentHarbor 管理权威记录与生效规则，腾讯用于受控提炼等局部能力，尚未实施 |
| 模型服务 | 是否接入 DeepSeek 模型或其他模型、用于哪些提炼步骤，尚未选定；这与 B 机是否使用 DeepSeek Harness 是两项不同决定 |
| 记忆读取接入 | 直接云端读取已确定；启动入口、首次请求前提供方式及确认依据仍需按实际智能体版本验证 |
| 自动提炼 | 候选与有效分开已确定；采集正文范围、触发时机、提炼质量待验证，不阻塞手动整理和读取 |
| 项目代码 | 云端是否托管仓库、使用哪个仓库服务尚未确定 |
| 云端部署 | 部署环境、地址和具体运行方式尚未确定 |

待定项不自动扩大首版范围，也不能当作已经实现或已经选定的能力。
