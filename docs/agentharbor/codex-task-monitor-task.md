# AgentHarbor 网页端 Codex 任务监控与 Bark 提醒

状态：已实现，当前机器已接入。第二台机器和 Bark 手机实收按用户决定延期。见[验收记录](codex-task-monitor-test-cases.md#本机验收记录)。

将 `codex-task-monitor` 的任务监控能力接入 AgentHarbor 的「智能体任务」页。Codex 在各台机器上照常运行，用户在网页统一查看任务、确认已处理并回看历史。开启 Bark 的用户在任务正常完成或中止时能收到手机提醒，网页关闭后也能收到。页面沿用 AgentHarbor 的设计。

本轮以 CIS 5480 跑通真实流程，再对账当前机器全部可读的存量任务，并持续采集新增。未匹配项目的任务归入「待归类」。

## 任务状态与范围

| 场景 | 预期行为 |
| --- | --- |
| 运行中 | 按会话展示最新一轮，可按项目或机器筛选。每条显示标题、项目、机器和最近更新时间。 |
| 待处理 | 一轮结束后标为「已完成」或「已中止」，等待用户确认。旧记录若只知道已结束，显示「结果未知」。 |
| 已处理 | 确认只作用于当前轮次。刷新或换浏览器后仍有效，记录在历史中可查。同一会话的新一轮结束后重新进入待处理。 |
| 存量接入 | 接入时仍在运行的任务进入监控列表，已结束且有记录的任务进入历史。已有明确处理记录的保留原状态，缺少处理记录的显示未知。 |
| 更新延迟 | 显示最后同步时间。断网或采集暂时失败时保留上次已知状态，提示数据可能过期。 |

## 开发任务

### 1. 本机采集与同步

- [x] 复用现有连接程序，只读获取 Codex 会话索引和运行记录，识别 `task_started`、`task_complete` 和 `turn_aborted`。按本机目录绑定匹配 AgentHarbor 项目，接入存量并持续采集新增。
- [x] 通过现有同步队列上传标题、项目、机器、会话 ID、轮次 ID、状态和时间。原始对话、完整日志和工作目录路径留在本机。
- [x] 支持断网排队、恢复补传和重复事件去重。旧轮次的结束事件晚到时，新轮次维持正确的状态。

### 2. 后端接口与网页

- [x] 在 Go API 和 PostgreSQL 中保存任务轮次和已处理记录，提供监控列表、历史查询和确认操作。沿用工作区和项目的访问校验。现有 Hook 的 `Stop` 只支持判断「已结束，结果未知」，明确结果以 Codex 日志中的事件为准。
- [x] 在现有「智能体任务」页展示运行中、待处理和历史。接上筛选、最后同步时间、过期提示和「已处理」操作。历史保留更早轮次。
- [x] 提供「在 Codex 打开」和「复制会话 ID」。浏览器所在机器的 Codex 能访问该会话时，深链打开对应正文。

### 3. Bark 设置与后台发送

- [x] 用户可在网页设置自己的 Bark 地址和密钥、发送固定文案的测试提醒，并随时开启或关闭。地址和密钥作为私密配置保存。
- [x] AgentHarbor 后台根据已同步的正常完成或中止事件发送提醒。通知标题使用任务标题，正文显示项目名和结果，例如「CIS 5480 · 已中止」。任务开始、历史导入和结果未知的记录不触发提醒。
- [x] 支持断网补传后触发提醒和失败重试。同一用户的同一轮任务重复上报只创建一条提醒。Bark 暂时不可用时，网页仍能显示结果并确认已处理。

## 验收清单

先用 CIS 5480 在主目录的 Docker 环境跑通，再对照纳入验收的全部机器和项目。验收时记录环境、对应任务和实际结果。

- [x] **本机任务接齐。** 对账已找到日志的轮次，可读存量与数据库一致。缺少日志的旧索引单独记录。
- [x] **状态准确。** 在 CIS 5480 的真实 Codex 会话验证了运行、正常完成和手动中止。
- [x] **确认可持久化。** 真实轮次确认后在历史可查，下轮中止后重新待处理。刷新和换登录由浏览器联调覆盖。
- [ ] **多机与补传。** 两台机器同时上报同一项目的任务，网页能区分来源。断网时可见最后同步时间，恢复后补齐结果，重复上报不产生重复记录，迟到的旧事件不覆盖新轮次。
- [ ] **Bark 真机收件。** 测试提醒能到手机。关闭网页后分别验证完成和中止提醒，核对标题、项目和结果。验证断网补传、重复上报、发送失败后重试，以及关闭提醒后新任务不再推送。
- [x] **打开正确会话。** 网页深链与真实会话 ID 一致，用户确认已打开对应 Codex 正文。复制会话 ID 由浏览器联调覆盖。
