随机值在验收父进程生成，验收环境变量从 Codex 子进程移除。提交、审核前、审核后各使用全新的隔离会话和配置。提交会话的配置和记录在接收会话运行前清理，保留的验收日志已隐藏随机值。接收会话中的随机值来自正式生效的记忆。

## 现有 Codex 配置复测

用户完成 Hook 信任后，`hooks/list` 在现有配置下返回 `testmem` 项目级 `SessionStart` 已启用且为 `trusted`。直接使用 Windows 桌面包自带的 app-server 开了新的临时会话 `01a1ebcb-ff78-7bb1-904a-25482b7de9d4`，搜索和提交两个 MCP 工具均可用。

服务端启动摘要选中了严格盲测批准的同一条目 `578fca92-519b-4d2c-90d2-4b343c444176`（修订 1）。首轮只执行一次启动 Hook，其输出先于模型输出，含对应条目及随机值。模型答对，零工具调用，轮次状态为 `completed`。随机值仅用于父进程比对，未写入提示、子进程环境或验收报告。脱敏证据为 `testmem-native-profile-verified.json`。

## 其他检查

- 连接助手用 Windows PowerShell 5.1 执行。重跑保留了无关 MCP 和已有 Hook，各只注册一条 AgentHarbor 配置。同名的自定义 TOML 表或键会提示冲突，文件哈希不变。普通注释或指令文字提到工具名仍能接入。已验证旧 stdio 配置升级。测试机执行策略会阻止带有下载标记的脚本，按页面帮助解除该文件的锁定后才运行。用户仍需选目录并按 Codex 提示审核 Hook。
- 项目 B 凭据查不到 A 的知识。把 A 配置复制到 B 的同级或嵌套目录后，B 的真实会话没有获得记忆工具，启动 Hook 给出失败提示。
- 另一个真实会话通过 MCP 搜索一条没有进入启动摘要的程序性记忆，并使用了返回的随机值。
- 模拟服务端提交成功后丢弃回执时，Codex 报告状态未确认。用原请求 ID 和原素材重试返回同一条记录，数据库仍只有一条。用原 ID 更换内容会冲突。修改后，新会话取得生效条目的修订 2，提交旧修订返回 HTTP 409。
- 对启动读取分别注入断连和 2.8 秒响应延迟。监听客户端 Hook 开始和结束事件的实测间隔分别为 3.363 秒和 5.489 秒，包含 Windows 进程启动。请求连接及读取超时设为 1.5 秒，Hook 外层上限为 8 秒。两种情况下 Hook 都提示读取失败，模型仍完成请求。恢复后，同一会话通过搜索取回知识，新会话重新自动读到记忆。
- 到期凭据返回 HTTP 401，取得新凭据后用原助手更新，桌面引擎恢复访问。分别关闭读取与写入，各自生效。停用条目后从启动摘要和搜索结果消失。
- 定向前端 Vitest 8 项通过，Views TypeScript、定向 ESLint、Go 后端构建与 `go vet` 通过。按仓库约定保留 Go 和桌面整套测试的暂停状态。
