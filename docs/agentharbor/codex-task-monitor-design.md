# Codex 任务监控与 Bark 技术方案

状态：已实现。本机接入结果与延期项见 [测试用例及验收记录](codex-task-monitor-test-cases.md)，功能范围见 [任务文档](codex-task-monitor-task.md)。

## 数据流

1. 连接程序在已绑定的项目目录下启用监控。只读访问 Codex 的 SQLite 会话索引与运行日志，按完整行提取开始、完成和中止。按项目一起保存扫描进度和待同步记录，离线时保持队列，恢复后按批确认。记录首次接入时间，用事件发生时间区分旧历史与断网期间的新终态。
2. 服务端按工作区、项目、机器、会话和轮次保存快照。一个轮次的终态优先于运行中。监控按实际开始时间选最新轮次，缺少开始时间的旧终态保留在历史，避免覆盖已确认的新运行。旧 Hook 和记忆回执仍通过原接口展示。旧 Stop 只能确认结果未知。
3. 网页在「智能体任务」页提供运行中、待处理、历史、项目及机器筛选、同步时间、确认和 Codex 会话入口。处理记录按用户和轮次保存。只迁移能确认的处理记录，其他存量处理状态显示未知。
4. 新的完成或中止事件落库时，同事务为同步凭据对应的用户创建 Bark 投递记录。后台独立投递并重试。启用前已结束、历史导入和结果未知不触发通知。地址和密钥加密保存，接口只返回配置状态。出站使用现有公网 HTTPS 连接检查，拒绝重定向；投递成功后的回执若丢失，外部推送可能重复。

上传内容限于任务元数据。Codex 的存储标题可能回退到首条输入，连接程序只上传能确认的会话名称，无法区分时使用通用标题。原始提示词和本地路径留在源机器。Bark 使用 [V2 推送接口](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)，消息内容为任务标题、项目名和结局。

本机整机接入使用本地项目映射。已确认目录归入对应项目，其余可读任务归入「待归类」。对现有索引里找不到的活动目录日志，可从明确指定的迁移备份恢复可匹配的历史终态。

## 接口约定

接口沿用现有 JSON 字段约定、工作区鉴权和 REST/JSON + fetch + Zod。同步成功确认整个批次，重发同一轮快照时状态收敛。

| 接口 | 约定 |
| --- | --- |
| POST /api/agentharbor/monitor/sync | 本机连接程序提交项目、机器、扫描结果和轮次快照。允许只报扫描状态。每个轮次带会话 ID、轮次 ID、标题、起止时间、运行结果、是否存量和是否已处理。最多 100 个轮次。 |
| GET /api/agentharbor/monitor | view=active 返回当前运行和待处理，view=history 返回分页历史。允许按项目和机器筛选，并返回每个来源的最后同步时间及过期状态。 |
| POST /api/agentharbor/monitor/handle | 按项目、机器、会话和轮次确认已处理，重复确认幂等。 |
| GET、PUT /api/agentharbor/monitor/bark | 读取当前用户在当前工作区的配置状态，保存地址、密钥和启用开关。更改开关可以保留已保存的凭据。 |
| POST /api/agentharbor/monitor/bark/test | 使用当前用户的已保存配置发送固定测试提醒。 |

Docker 后端使用与部署绑定的 `AGENTHARBOR_BARK_SECRET_KEY` 加密 Bark 配置。由部署者生成并保存 32 字节的随机密钥，以 Base64 写入环境配置。网页配置 Bark 服务器的公网 HTTPS 地址和手机端设备密钥。

## 验收顺序

按 [测试用例](codex-task-monitor-test-cases.md) 先做合成数据验证，再用主目录的 Docker 环境跑 CIS 5480。最终验收分别记录全部接入范围的对账结果、两台真实机器的同步结果和 Bark 手机实收。

本轮用户确认只接入当前机器可读取的任务，第二台机器和 Bark 手机实收延期。Bark 配置和后台投递仍通过合成用例验证。
