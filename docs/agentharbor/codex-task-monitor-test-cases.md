# Codex 任务监控与 Bark 测试用例

状态：CT-01–09 自动验证与 CT-10 本机真机验收已执行。CT-11 已完成当前机器对账，第二台机器和 CT-12 手机实收延期。需求见 [任务文档](codex-task-monitor-task.md)，设计见 [技术方案](codex-task-monitor-design.md)。

自动用例使用合成的 SQLite、rollout、数据库和 Bark 响应。最终验收从主目录的 Docker 环境开始，用 CIS 5480 跑通后，再按完整的机器与项目清单对账。

## 自动用例

| 编号 | 准备与操作 | 预期结果 |
| --- | --- | --- |
| CT-01 存量导入 | 准备一个在跑的轮次、两个已结束的轮次（其中一个有原监控器的处理记录），以及另一个目录下的轮次。在绑定项目上首次同步。 | 运行中轮次出现。两个结束轮次可在历史查到，分别显示已处理和处理状态未知。其他目录的轮次不进入该项目。存量结束不触发提醒。 |
| CT-02 最新轮次 | 同一会话先上报新一轮开始，再补报旧轮完成；随后上报新轮中止，再重放其开始事件。 | 旧轮可在历史查到；新轮保持运行中，直至收到自己的中止事件。重放开始不会退回运行中。 |
| CT-03 轮次确认 | 使用账号 A 确认一轮，重复确认，再用 A 刷新页面和重新登录。用有项目访问权限的账号 B 查询，最后在同一会话运行下一轮。 | A 只从待处理移除这一轮，历史仍可查。B 的处理状态独立。下一轮结束后对 A 重新可见。运行中的轮次不可确认。 |
| CT-04 断网续传 | 上传开始事件后断开网络，写入结束事件。重启连接程序并恢复网络，模拟服务端已接收但连接程序未收到确认，再次同步。 | 网页保留最后状态并显示同步时间；恢复后补齐结局。同一轮只有一条记录，同一用户只创建一条提醒。 |
| CT-05 日志兼容 | 写入尚未换行的终态 JSON，下一次扫描前补齐；再模拟日志暂时不可读、归档路径变化和中止记录缺少开始时间。 | 半条记录不会产生终态，补齐后只产生一次。读取失败提示可能过期，不清空已知状态。能确认的中止仍可查，开始时间未知的旧记录不会盖过已确认的新运行。 |
| CT-06 隔离和隐私 | 用其他工作区的项目 ID 查询、同步和确认。把原始用户提示词写入 SQLite 标题及会话命名回退样本，检查队列、API 请求和错误日志。 | 跨范围请求被拒绝。上传只含规定元数据，原始提示词、绝对目录、日志正文和 Bark 密钥不进入上传体或错误日志。 |
| CT-07 Bark 配置 | 配置测试地址和设备密钥，关闭任务通知，再发送固定文案的测试提醒。用另一账号读取设置。 | 测试提醒可独立验证配置，回读只返回是否已配置和启用状态。其他账号读不到配置。 |
| CT-08 Bark 条件与重试 | 模拟一次完成和一次中止，再上报开始、存量结束和结果未知。让假 Bark 首次失败、重试成功，然后关闭提醒并补报一项新结束。 | 两类明确终态的标题、项目和结局正确。其他事件不发送。失败期间网页照常显示结果和确认操作。重试成功后不继续重发，关闭后新任务不创建提醒。 |
| CT-09 页面筛选与历史 | 用同一项目的两台合成机器上报任务，准备超过一页的历史。切换项目、机器和历史页，模拟刷新失败。 | 来源区分正确，筛选和历史翻页有效。刷新失败保留已有数据。复制的是原会话 ID，合法会话才生成 Codex 深链。 |

## 真实设备验收

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| CT-10 CIS 5480 试点 | 在绑定的项目目录运行两轮真实 Codex，一轮完成，一轮手动中止。网页确认处理后换浏览器检查，再开一轮。 | 网页能看到运行中与两类终态。确认按轮保存，历史可查，新轮可重新进入待处理。在能访问该会话的机器点击「在 Codex 打开」可打开正文。 |
| CT-11 全量与两机 | 列出约定接入的机器和项目，核对每组存量可读轮次与网页。用两台机器并行运行同一项目，其中一台断线后补传。 | 存量和新增都能核对，来源正确。每个差异都记录具体原因。两机并行和恢复同步后，网页状态与本机一致。 |
| CT-12 Bark 手机实收 | 在网页保存 Bark 配置，确认手机收到测试提醒。关闭网页，完成一轮、中止一轮，再验证断网结束后的补发。关闭提醒后另跑一轮。 | 手机收到测试、完成、中止和补传提醒，文案与任务一致。关闭后新任务无提醒，网页恢复访问后仍可查看结果。发送失败和重试行为以 CT-08 的可控验证补充。 |

验收记录按「用例编号、机器、项目、会话与轮次、实际结果、证据或差异原因」填写。Bark 实收记录只保留通知结果与脱敏截图。
